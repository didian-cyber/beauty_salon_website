# Функциональные требования MVP

## Основные модули системы

### Модуль "Главная страница и навигация"

1. Система должна отображать главную страницу с баннером, содержащим название салона "Beauty&tochka" и описание
2. Система должна предоставлять навигационное меню с разделами: "Главная", "Услуги", "Мастера", "Запись"
3. Система должна обеспечивать адаптивное отображение контента для устройств с шириной экрана от 320px до 1920px
4. Система должна отображать контактные данные салона в футере сайта

## Модуль "Услуги"

1. Система должна отображать каталог услуг в виде карточек ServiceCard, каждая из которых содержит: название, описание, изображение и состояние выбора
2. Система должна отображать 6 основных услуг: маникюр, педикюр, стрижка и окрашивание, ресницы, брови, депиляция
3. Система должна отображать карточки услуг в адаптивной сетке (3 колонки на десктопе, 1 на мобильных)

## Модуль "Мастера"

1. Система должна отображать галерею мастеров с использованием компонента MasterPhotoCard со слайдерами работ
2. Система должна предоставлять фильтрацию мастеров по 4 специализациям: маникюр/педикюр, брови/ресницы, парикмахеры, депиляция
3. Система должна отображать информацию о каждом мастере: имя, должность, опыт работы

## Модуль "Онлайн-запись"

1. Система должна предоставлять форму для онлайн-записи с полями: "Имя" (текстовое поле, обязательное), "Телефон" (поле с валидацией номера, обязательное), "Услуга", "Мастер"
2. Система должна сохранять данные записи в локальное хранилище

## Модуль "Авторизация"

1. Система должна предоставлять форму авторизации для администраторов с полями "Логин" и "Пароль"
2. Система должна проверять корректность учетных данных и предоставлять доступ к панели управления только после успешной аутентификации

## Модуль "Управление услугами"

1. Система должна предоставлять интерфейс для просмотра списка всех услуг
2. Система должна позволять добавлять новые услуги, редактировать существующие (название, описание, цена, изображение) и удалять услуги
3. Система должна валидировать вводимые данные (неотрицательная цена, заполненные обязательные поля)

## Модуль "Управление мастерами"

1. Система должна предоставлять интерфейс для просмотра списка всех мастеров
2. Система должна позволять добавлять новых мастеров, редактировать существующих (имя, должность, опыт, фото, работы) и удалять мастеров
3. Система должна предоставлять возможность загрузки нескольких фото работ для каждого мастера

## Модуль "Управление записями"

1. Система должна отображать список записей клиентов с информацией об имени, телефоне, услуге, мастере и дате записи
2. Система должна предоставлять возможность подтверждения, отмены и удаления записей

## Технические требования

- Два независимых проекта: клиентское приложение + админ-панель
- ES6 modules 
- TypeScript
- Локальное хранение данных в JSON-файлах
- Запрещены: require, module.exports, var

## Use Case: Просмотр главной страницы

### Участники
Клиент, Система отображения контента
### Предусловия
- Клиент зашел на главную страницу
- Система загрузила основной контент

### Основной сценарий
1. Клиент переходит на главную страницу
2. Система показывает основной баннер с названием салона "Beauty&tochka"
3. Клиент листает страницу вниз
4. Система отображает блок "Услуги" с сеткой карточек ServiceCard
5. Клиент знакомится с услугами салона
6. Система показывает блок "Мастера" с фильтрацией по категориям
7. Клиент просматривает мастеров и их работы в слайдерах MasterPhotoCard
8. Система отображает контакты салона в футере
9. Клиент записывается на услугу через навигацию 

### Результат
Клиент ознакомился с услугами салона и мастерами, может записаться на процедуру
### Альтернативный сценарий
- При ошибке загрузки система показывает страницу 404
- Клиент обновляет страницу для повторной попытки

## Use Case: Онлайн-запись на услугу

### Участники
Клиент, Система онлайн-записи
### Предусловия
- Клиент находится на сайте салона
- Клиент ознакомился с услугами и мастерами

### Основной сценарий
1. Клиент нажимает кнопку "Запись" в навигации
2. Система открывает страницу онлайн-записи
3. Клиент выбирает услугу из списка доступных
4. Клиент выбирает мастера 
5. Клиент заполняет поле "Имя"
6. Клиент заполняет поле "Телефон"
7. Клиент нажимает кнопку "Подтвердить запись"
8. Система проверяет корректность заполнения полей
9. Система сохраняет запись в базе данных
10. Система показывает сообщение об успешно созданной записи

### Результат
Клиент успешно записался на услугу, система сохранила данные и показала подтверждение

### Альтернативный сценарий
1. Система обнаруживает, что поле "Телефон" заполнено некорректно
2. Система подсвечивает поле красным и показывает сообщение "Введите корректный номер телефона"
3. Клиент исправляет номер телефона
4. Возврат к шагу 7

## Use Case: Просмотр каталога услуг
### Участники
Клиент, Система отображения контента
### Предусловия
- Клиент находится на сайте
- Система загрузила актуальный каталог услуг

### Основной сценарий
1. Клиент нажимает на пункт меню "Услуги"
2. Система отображает страницу с каталогом услуг в виде карточек ServiceCard
3. Система показывает название, описание, изображение и состояние выбора для каждой услуги
4. Клиент просматривает доступные услуги
5. Клиент может выбрать услугу для дальнейшей записи

### Результат
Клиент ознакомился с доступными услугами салона красоты

### Альтернативный сценарий
1. Доступных услуг нет
2. Система показывает сообщение "В настоящий момент услуги временно недоступны"
